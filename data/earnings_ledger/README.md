# Earnings Event Ledger

`data/earnings_ledger/` は、新規に公表された決算・業績関連開示の正準 GitHub 台帳です。

## 契約

収集処理は必ず次の順序で動きます。

1. 実行時刻を `T_end` とし、`T_start = T_end - 24h` を固定する。
2. 一次情報だけから候補を発見する。
3. 内容を読む前に一次情報上の公表時刻を確認する。
4. 古い資料、未来時刻、重複、決算無関係、時刻未確認候補を棄却する。
5. 採用台帳と棄却台帳を分離して保存する。
6. 決定論的な監査を実行する。
7. PASS イベントだけから閲覧用 Markdown を生成する。

検索エンジンの日付、クロール日、再掲日、記事更新日は公表日時として使いません。

## ファイル

- `source_registry.json` — 監視対象と一次情報ソース。
- `events.ndjson` — 鮮度ゲートを通過したイベント台帳。
- `rejected.ndjson` — 棄却理由を持つ候補台帳。
- `state.json` — 最新収集窓と件数。
- `audit_latest.json` — 最新の決定論的監査結果。
- `reports/YYYY-MM-DD.md` — 日次閲覧用レポート。

LLM に欠損した公表時刻、決算期、数値、コンセンサスを補完させません。

## SEC EDGAR

- `8-K` は Item `2.02` がある場合のみ採用。
- `10-Q`、`10-K`、`20-F` は財務報告イベントとして採用。
- `6-K` は一次文書そのものを取得し、厳格な決算キーワードゲートを通過した場合のみ採用。
- 鮮度の正準時刻は SEC `acceptanceDateTime`。

## JPX TDnet

公式 `release.tdnet.info` の日次一覧を巡回し、開示時刻、証券コード、会社名、表題、一次 PDF URL を取得します。対象企業コードかつ決算・業績関連タイトルだけを採用します。

鮮度の正準時刻は TDnet の開示日＋開示時刻（JST）です。

## 未対応ソース

正確な公表時刻を取得するアダプターがない情報源は推測せず `enabled: false` にします。`audit_latest.json` の `unsupported_or_disabled_sources` が改善待ち台帳になります。

## 再試行・自己監査

GitHub Actions は次を行います。

- 2時間ごと、17分に実行。
- 一時障害時は最大3回まで収集を再試行。
- pytest と台帳監査を実行。
- 監査済みの台帳・レポート変更だけを commit / push。
- 有効な一次情報アダプターの障害または台帳監査失敗では fail closed。

毎朝の決算通知タスクは、この台帳と最新 Action 状態を最初に監査します。安全で決定論的な修正が可能なら、収集器を修正・テスト・mergeし、失敗 Action を再実行した後、通常の決算サマリーを出力します。定常的な修復でユーザー確認を要求しません。
